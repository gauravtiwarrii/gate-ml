Status: planned — not yet integrated

How Claude fits GATE ML

No Claude integration exists in the product today — verified: the codebase has zero API calls, zero keys, zero backend. Below is the concrete plan for which Claude credits would be used, so a reviewer can see exactly what would be built.

Planned capabilities (all labelled)

Planned Hint ladder — step-by-step hints per question (concept nudge → formula → worked first step), never full answer first.
Planned Explain my miss — grounded in the guide unit + official solution; cites unit/section.
Planned Practice generation — new MCQ/MSQ/NAT variants in GATE pattern, human-reviewed before publishing.
Planned Study planner — 90-day plan adapted from mock weakest-topic report.
Not planned Auto-grading replacement, exam prediction, or any claim of affiliation with GATE/IITs.

Architecture (to be built)

Thin server proxy (Vercel serverless) holds ANTHROPIC_API_KEY server-side only. Client sends: question ID + attempt + guide-section context. Model: Claude Sonnet for explanations, Haiku for hints (cost/latency). Guardrails: system prompt constrains to syllabus; temperature low; max tokens capped; per-IP + per-day rate limits; abuse logging; opt-in toggle (offline mode stays default). No PII sent; prompts contain only question text + attempt.

browser (static) --HTTPS--> /api/claude-hint {qid, attempt}
  server: inject guide context + system prompt
  server --HTTPS--> api.anthropic.com (key in env only)
  server: validate, cache, rate-limit --> browser

Security & cost control

Keys never in client or repo. Input validation + length caps. Output length caps. Response caching per question. Kill-switch + usage dashboard. Privacy: localStorage progress never leaves device unless user opts into AI hints.

What credits would fund

Prototype API usage, eval of hint quality vs. static solutions, and a small beta (rate-limited). No fine-tuning; prompt engineering + retrieval from our own guide only.
